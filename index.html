Claude Code คืออะไร

Claude Code เป็นผู้ช่วยเขียนโค้ดแบบ agent ไม่ได้แค่ตอบคำถาม แต่ลงมือทำงานในเครื่องคุณได้เอง เช่น อ่านและแก้ไฟล์ รันคำสั่ง PowerShell/Bash ค้นหาโค้ด เปิดเบราว์เซอร์ทดสอบเว็บ และทำงานกับ git/GitHub

ใช้ได้หลายช่องทาง ได้แก่ CLI ใน terminal (claude), Desktop app บน Mac/Windows (แท็บ Code), เว็บ claude.ai/code และ extension ของ VS Code / JetBrains ทุกช่องทางใช้ engine และไฟล์ตั้งค่าชุดเดียวกัน

ส่วนของหน้าจอหน้าที่
Sidebar ซ้ายรายการ session ทั้งหมด จัดเป็นกลุ่มหรือ section ได้
Transcript กลางบทสนทนา ผลการใช้ tool และ task list ที่ Claude อัปเดตระหว่างทำงาน
ช่องพิมพ์ด้านล่างพิมพ์คำสั่ง แนบไฟล์/รูป เลือก model, permission mode และ effort
Pane ขวาDiff, Terminal, Browser, PR, Tasks, Plan, Artifacts

PROpen PR คืออะไร

Pull Request คือ คำขอให้นำโค้ดจาก branch หนึ่งไปรวมเข้ากับอีก branch ซึ่งมักเป็น main PR ทำหน้าที่เป็นพื้นที่กลางของการเปลี่ยนแปลงชุดนั้น แสดง diff ให้คนอื่น review และคอมเมนต์รายบรรทัด รัน CI (เช่น pytest หรือ lint) ก่อนรวม และเก็บประวัติว่าใครแก้อะไร ทำไม เมื่อไร

วงจรชีวิตของ PR
main ──●──────────────────────────●──  (merge แล้ว)
        \                        /
feature  ●──●──●  → push → PR → review → CI ✓ → merge
        (commit)          (แก้ตามคอมเมนต์ → push เพิ่ม)
  1. สร้าง branch เช่น feature/add-rsi
  2. Commit การแก้ไข
  3. Push ขึ้น GitHub
  4. Open PR พร้อมชื่อและคำอธิบายว่าแก้อะไร ทำไม และทดสอบอย่างไร
  5. CI รันอัตโนมัติ ถ้าล้มก็แก้แล้ว push ใหม่ PR จะอัปเดตเอง
  6. Review และแก้ตามคอมเมนต์
  7. Merge เข้า main แล้วลบ branch

มี Draft PR สำหรับงานที่ยังไม่เสร็จ แต่อยากให้คนเห็นหรือให้ CI รันไปก่อน

Claude Code ช่วยอะไรได้บ้าง

เมื่อแก้โค้ดเสร็จใน git repo แอปจะมีปุ่ม Commit และ Create PR หรือจะพิมพ์ว่า "เปิด PR ให้หน่อย" ก็ได้ Claude จะสร้าง branch, commit, push แล้วเปิด PR ด้วย gh pr create พร้อมเขียนคำอธิบายให้ จากนั้น PR จะผูกเข้ากับ session

ฟีเจอร์ทำอะไร
CI statusดูผล test ใน PR pane
Auto-fixแอปเฝ้าดู PR ให้ ถ้า CI ล้ม มี conflict หรือมีคอมเมนต์ จะให้ Claude แก้และ push เอง
Fix CI / Address comments / Resolve conflictsสั่งแก้แต่ละเรื่องแบบครั้งเดียว
Auto-mergemerge อัตโนมัติเมื่อทุกอย่างผ่าน (เปิดเฉพาะเมื่อสั่ง)
ตัวอย่าง

"เพิ่มฟังก์ชันคำนวณ RSI ใน indicators.py พร้อม test แล้วเปิด PR" Claude จะเขียนโค้ด รัน pytest สร้าง branch และเปิด PR ถ้า CI บน GitHub ล้มเพราะ Python คนละเวอร์ชัน Auto-fix จะอ่าน log แก้ไข แล้ว push ให้

เงื่อนไข

โฟลเดอร์ต้องเป็น git repo ที่มี GitHub remote และต้องติดตั้งและ login GitHub CLI (gh auth login) แล้ว

Git Worktree

ถ้าสอง session แก้ไฟล์ในโฟลเดอร์เดียวกันพร้อมกัน งานจะทับกัน worktree แก้ปัญหานี้ด้วยการ checkout branch อื่นไปไว้อีกโฟลเดอร์ โดยใช้ repo ร่วมกัน

โครงสร้าง
stock\                 ← main (โฟลเดอร์หลัก)
stock-worktrees\
  ├─ add-macd\         ← branch feature/add-macd  (session A)
  └─ fix-commission\   ← branch fix/commission    (session B)

ใน Desktop app ตอนสร้าง session ในโฟลเดอร์ที่เป็น git repo ให้เลือกใช้ worktree แอปจะสร้าง branch และโฟลเดอร์ให้ แล้วเก็บกวาดให้เมื่อ archive

ทำเองด้วยคำสั่ง
git worktree add ../stock-macd -b feature/add-macd

ตัวอย่าง: session A เพิ่ม indicator MACD ขณะที่ session B แก้บั๊ก backtest ที่คิด commission ผิด ทั้งคู่ทำงานพร้อมกันและเปิด PR ของตัวเองได้โดยไม่ชนกัน

# Stock Analysis Project

## ภาพรวม
วิเคราะห์หุ้น SET ด้วย Python: ดึงข้อมูล → คำนวณ indicator → backtest → รายงาน

## Environment
- Python 3.11, venv ที่ `.venv`
- รัน: `.venv\Scripts\python main.py`
- ทดสอบ: `.venv\Scripts\pytest -q`

## โครงสร้าง
- `data/` ข้อมูลดิบ (ห้ามแก้ ห้ามลบ)
- `indicators/` pure function รับ DataFrame คืน Series
- `backtest/` engine และ strategy

## กฎ
- ใช้ pandas แบบ vectorize ห้าม loop บน DataFrame ถ้าไม่จำเป็น
- ราคาเป็น THB วันที่เป็น Asia/Bangkok
- ตอบภาษาไทย ชื่อตัวแปรภาษาอังกฤษ
- indicator ใหม่ทุกตัวต้องมี test ใน `tests/`

@docs/strategy-notes.md
  • บรรทัด @path ใช้ import ไฟล์อื่นเข้ามาเป็นบริบท
  • เริ่มด้วย /init ให้ Claude ร่างให้ก่อน แล้วค่อยปรับ
  • เขียนสั้นและชัด เพราะทุกบรรทัดกิน token ทุกครั้ง
  • ถ้า Claude ทำผิดซ้ำ ให้เพิ่มกฎลงไฟล์นี้

Permissions และ settings.json

ใช้ลดการขออนุญาตซ้ำ ๆ และกันไม่ให้ Claude แตะสิ่งที่ไม่ควรแตะ

ไฟล์ขอบเขต
~\.claude\settings.jsonทุกโปรเจกต์
.claude\settings.jsonโปรเจกต์ แชร์ทีมได้
.claude\settings.local.jsonโปรเจกต์ เฉพาะคุณ
.claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(python:*)",
      "Bash(pytest:*)",
      "Bash(git status)",
      "Bash(git diff:*)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)",
      "Bash(rm -rf:*)"
    ]
  }
}

ความหมายคือ รัน python และ pytest ได้โดยไม่ต้องถาม แต่ห้ามอ่านไฟล์ API key และห้ามลบแบบ recursive ถ้าไม่อยากเขียนเอง ใช้ /fewer-permission-prompts ให้ Claude สแกนประวัติแล้วเสนอ allowlist ให้

แบ่งสิทธิ์เป็น 3 ระดับ

อนุญาตมากเกินไปเสี่ยงต่อข้อมูล อนุญาตน้อยเกินไป Claude ก็หยุดถามบ่อยจนทำงานต่อเองไม่ได้ แบ่งเป็น 3 ระดับตามความเสี่ยง และตั้งแต่ละระดับไว้คนละไฟล์

ระดับคำสั่งตั้งไว้ที่ไหน
1 · อนุญาตทั้งเครื่องคำสั่งอ่านอย่างเดียว: git status/diff/log/show, git branch แบบดูรายการ, gh pr view/list/status, conda list, pip list/show~\.claude\settings.json ในส่วน allow
2 · อนุญาตเฉพาะโปรเจกต์python, pytest ในโปรเจกต์ที่ไม่มีรหัสผ่าน ไม่เชื่อมบัญชีการเงิน และไม่ส่งข้อมูลออก เช่น งานวิจัย<project>\.claude\settings.local.json ของโปรเจกต์นั้น
3 · ต้องถามทุกครั้งpython ในโปรเจกต์ที่มีข้อมูลการเงินหรือส่งคำสั่งซื้อขาย, git commit/push, gh pr create, pip/conda/mamba installไม่ต้องตั้ง แค่ไม่ใส่ไว้ในรายการ allow
ห้าม (deny)อ่าน .env, secrets/, ไฟล์ config ที่มีรหัส, .credentials.json, .ssh/~\.claude\settings.json ในส่วน deny
ระดับ 2 · <project>\.claude\settings.local.json
{
  "permissions": {
    "allow": [
      "PowerShell(python *)",
      "PowerShell(pytest *)",
      "Bash(python *)",
      "Bash(pytest *)"
    ]
  }
}
ข้อควรรู้
  • อนุญาต python เท่ากับอนุญาตให้รันโค้ดอะไรก็ได้ จึงไม่ควรตั้งทั้งเครื่อง
  • กฎ deny แบบ Read(...) กันไม่ให้ Claude เปิดอ่านไฟล์โดยตรง แต่ไม่กันสคริปต์ที่ Claude รัน ด่านที่กันได้จริงคือการไม่อนุญาต python ในโปรเจกต์ที่มีข้อมูลลับ
  • อย่าอนุญาต git branch * ทั้งหมด เพราะจะรวมคำสั่งลบ branch (git branch -D) ไปด้วย
  • ถ้าลืมว่าตั้งอะไรไว้ ถาม Claude ว่า "ตอนนี้อนุญาตคำสั่งอะไรไว้บ้าง" Claude จะเปิดไฟล์ตั้งค่าแล้วสรุปให้

Hooks

Hook คือคำสั่ง shell ที่ ระบบรันเองตามเหตุการณ์ Claude ไม่ได้เป็นผู้ตัดสินใจ จึงรับประกันได้ว่าเกิดขึ้นทุกครั้ง

Eventเกิดเมื่อ
PreToolUseก่อนใช้ tool (บล็อกได้)
PostToolUseหลังใช้ tool
UserPromptSubmitเมื่อคุณส่งข้อความ
Stopเมื่อ Claude ตอบเสร็จ
SessionStartเมื่อเริ่ม session
Notificationเมื่อ Claude รอคุณตอบ
format โค้ดทุกครั้งที่แก้ไฟล์
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "ruff format ." }
        ]
      }
    ]
  }
}

ไอเดียอื่น: ใช้ Stop รัน pytest ทุกครั้งที่ทำงานเสร็จ, ใช้ PreToolUse บล็อกการแก้ไฟล์ใน data/ หรือใช้ Notification ส่งเสียงเตือน ถ้าไม่อยากเขียน JSON เอง บอกเป็นภาษาธรรมดาได้ เช่น "ทุกครั้งที่แก้ไฟล์ .py ให้รัน ruff"

MCP

MCP (Model Context Protocol) คือปลั๊กอินที่เพิ่ม tool ใหม่ให้ Claude เช่น ฐานข้อมูล, Google Calendar, Slack, Notion หรือ API ภายในองค์กร

เพิ่มผ่าน CLI
claude mcp add sqlite -- npx -y @modelcontextprotocol/server-sqlite --db-path ./stock.db
.mcp.json · แชร์กับทีม
{
  "mcpServers": {
    "sqlite": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-sqlite", "--db-path", "./stock.db"]
    }
  }
}

จากนั้นถามได้เลย เช่น "หุ้นตัวไหนมี volume เฉลี่ย 20 วันสูงสุด" Claude จะ query ให้ ใน Desktop app ยังมี Connectors ที่เชื่อมผ่านบัญชี claude.ai ได้โดยไม่ต้องตั้งค่าเอง

ใช้ Desktop เมื่อ

  • อยากเห็นภาพรวมและรีวิว diff ชัด ๆ
  • ทำหลายงานและสลับไปมาบ่อย
  • ทำเว็บหรือ dashboard แล้วอยาก preview ทันที
  • งานเอกสาร Excel/Word/PDF หรือควบคุมแอป
  • ใช้ PR พร้อม Auto-fix

ใช้ CLI เมื่อ

  • ถนัดคีย์บอร์ดและต้องการความเร็ว
  • ทำ automation ด้วย script หรือ Task Scheduler
  • ทำงานบน Linux หรือ GPU server ผ่าน SSH
  • ต้อง pipe ข้อมูลกับเครื่องมืออื่น
  • เครื่องสเปกต่ำ หรือใช้ terminal ใน IDE อยู่แล้ว

แนะนำให้ใช้ผสมกัน ใช้ Desktop สำหรับงานประจำวันและการรีวิว และใช้ CLI (claude -p) สำหรับงานอัตโนมัติหรือบน server

Artifacts และการจ่ายเงิน

Artifact คือหน้าเว็บส่วนตัวบน claude.ai ที่ Claude สร้างให้และแชร์ลิงก์ได้ ข้อมูลจากศูนย์ช่วยเหลือของ Anthropic มีดังนี้

  • ถ้าไม่ต่ออายุ แผน Pro/Max ยังใช้ได้จนจบรอบบิล แล้วบัญชีจะกลับเป็นแผน Free โดยข้อมูลไม่ถูกลบ
  • แผน Free ยังเผยแพร่ artifact ได้ แต่ artifact จะผูกอยู่กับแชทที่สร้างมัน
  • เอกสารไม่ได้ระบุว่าลิงก์ที่เผยแพร่ไว้จะยังเปิดได้ช่วงแผน Free หรือไม่ และฟีเจอร์ขั้นสูง เช่น ฐานข้อมูลร่วม อาจใช้ไม่ได้
กู้คืนไม่ได้

ถ้ากด Unpublish หรือลบ artifact จะกู้คืนไม่ได้ และข้อมูลที่หน้าเว็บเก็บไว้จะหายถาวร

หน้าเว็บที่ต้องเปิดได้ตลอด ควรเก็บไฟล์ HTML ต้นฉบับไว้ในเครื่อง แล้วเผยแพร่บน GitHub Pages ตามหัวข้อถัดไป

เผยแพร่บน GitHub Pages

GitHub Pages โฮสต์หน้าเว็บ static (HTML/CSS/JS) ได้ฟรี ที่อยู่จะเป็น https://<username>.github.io/<repo>/ และไม่ขึ้นกับการจ่ายเงินให้ claude.ai

วิธีที่ 1 · ผ่านหน้าเว็บ GitHub (ไม่ต้องใช้ git)

  1. สมัครหรือ login บัญชีที่ github.com
  2. กด New repository ตั้งชื่อ เช่น claude-code-guide แล้วเลือก Public (บัญชีฟรีใช้ Pages ได้กับ repo สาธารณะเท่านั้น)
  3. ใน repo กด Add file → Upload files แล้วอัปโหลดไฟล์ index.html จากนั้นกด Commit changes
  4. ไปที่ Settings → Pages ตั้ง Source เป็น Deploy from a branch แล้วเลือก Branch main และโฟลเดอร์ / (root) จากนั้นกด Save
  5. รอ 1–2 นาที แล้วเปิด https://<username>.github.io/claude-code-guide/

ข้อควรรู้
  • Repo และหน้าเว็บเป็น สาธารณะ ทุกคนเห็นได้ ห้ามใส่ API key รหัสผ่าน หรือข้อมูลส่วนตัว
  • รองรับแค่หน้าเว็บ static ความสามารถของ artifact เช่น ฐานข้อมูลร่วมหรือการถาม Claude จากหน้าเว็บ จะใช้ไม่ได้
  • ถ้าตั้งชื่อ repo เป็น <username>.github.io หน้าเว็บจะอยู่ที่ root เช่น https://<username>.github.io/ ใช้ทำหน้ารวมลิงก์ไปยังเว็บอื่น ๆ ได้
  • เปิด https://<username>.github.io/ แล้วขึ้น "There isn't a GitHub Pages site here" แปลว่ายังไม่มี repo ชื่อ <username>.github.io เว็บของ repo อื่นต้องเติมชื่อ repo ต่อท้าย เช่น /claude-code-guide/

Miniforge
  • Miniforge ใช้ channel conda-forge เป็นค่าเริ่มต้น และมี mamba ที่ติดตั้งแพ็กเกจได้เร็วกว่า conda มาก สคริปต์จะใช้ mamba สร้าง environment ให้
  • รุ่น CondaForge.Miniforge3 ใช้ Python ปกติ (CPython) ถ้าเครื่องเก่าเป็นรุ่น Miniforge-pypy3 ไม่จำเป็นต้องติดตั้งรุ่น PyPy อีก เพราะ environment แต่ละตัวระบุเวอร์ชัน Python ของตัวเองไว้ในไฟล์ .yml อยู่แล้ว
  • conda บน Windows มักไม่อยู่ใน PATH สคริปต์สำรองจึงหา conda จากไฟล์ ~\.conda\environments.txt และ export ทุก environment ที่ลงทะเบียนไว้ รวมถึงตัวที่สร้างจาก Anaconda รุ่นเก่า
  • Environment ที่ใช้ Python 2 หรือ 3.7 อาจสร้างใหม่ไม่ได้ เพราะ conda-forge เลิกทำแพ็กเกจรุ่นเก่าแล้ว สคริปต์จะแจ้งเตือนแล้วทำตัวถัดไปต่อ ตัวที่ใช้งานจริงควรอัปเกรดเวอร์ชัน Python ในไฟล์ .yml ก่อนสร้าง

ถ้าอยากได้โปรแกรมครบเหมือนเครื่องเก่าทุกตัว สคริปต์สำรองจะบันทึกรายการไว้ใน winget-apps.json ใช้คำสั่ง winget import -i winget-apps.json บนเครื่องใหม่ได้ แต่จะติดตั้งทุกอย่างรวมถึงโปรแกรมที่ไม่เกี่ยวกับ Claude ด้วย

Session บนเครื่อง remote

Session ที่เปิดบนเครื่องอื่น (ผ่าน Remote Control หรือ SSH) เก็บประวัติแชทและไฟล์งานไว้ในเครื่องนั้น Desktop app บนเครื่องที่คุณใช้อยู่แค่แสดงผล พอปิดเครื่อง remote session จะหายจาก sidebar แต่ไม่ได้ถูกลบ เปิดเครื่องกลับมาก็เห็นอีก

ทางเลือกเหมาะเมื่อข้อจำกัด
A. ย้ายมาทำที่เครื่องหลัก (แนะนำ)ใช้เครื่องนี้ทำงานเป็นหลักประวัติแชทไม่ตามมาเต็ม ๆ ต้องให้ session เดิมเขียนสรุปส่งต่อไว้
B. Move to cloudอยากให้ทำงานต่อได้แม้ปิดทุกเครื่องต้องเป็น GitHub repo และ cloud เป็น Linux แก้โค้ดได้ แต่โปรแกรม Windows UI หรืองานที่ต้องต่อกล้องหรือฮาร์ดแวร์จะรันทดสอบไม่ได้
C. เปิดเครื่อง remote ทิ้งไว้เครื่องนั้นต่อฮาร์ดแวร์ที่ต้องใช้ทดสอบเปลืองไฟ และต้องตั้งไม่ให้เครื่อง sleep

ย้ายจาก Pro ไป Team

เมื่อเข้าร่วมองค์กรแผน Team มีสองทางให้เลือก ทางแรกคือ ย้าย ข้อมูลจากบัญชีส่วนตัวเข้าองค์กร ทางที่สองคือ แยก ใช้บัญชีส่วนตัวกับบัญชีองค์กรคู่กัน โดยติ๊ก "Keep your personal account separate" ตอนเข้าร่วม

ข้อมูลถ้าเลือกย้าย
แชท และ artifact ในแชทย้ายตาม
Projects พร้อมคำสั่ง ไฟล์ และการตั้งค่า syncย้ายตาม
Memory ของแชทและ Projectsย้ายตาม ถ้าองค์กรเปิดฟีเจอร์ memory
การตั้งค่าส่วนตัวของ Claude Codeย้ายตาม ยกเว้นองค์กรกำหนดค่าไว้แล้ว
Artifact ที่เผยแพร่เป็นลิงก์สาธารณะไม่ย้าย
Skills ที่สร้างเองไม่ย้าย ต้อง export ก่อน
Connectorsต้องเชื่อมใหม่ ส่วน connector ที่เพิ่มเองต้องเพิ่มใหม่
ลิงก์แชร์แชท และคำเชิญแชร์ที่ค้างอยู่ไม่ย้าย

ไฟล์ Claude Code ในเครื่อง (~\.claude) และไฟล์โปรเจกต์ไม่กระทบ อยู่ในเครื่องอยู่แล้ว แค่ login ใหม่ด้วยบัญชี Team
หน้าเว็บบน GitHub Pagesไม่กระทบ อยู่นอก claude.ai
ย้อนกลับไม่ได้
  • ข้อมูลที่ย้ายเข้าองค์กรแล้ว ย้ายกลับมาบัญชีส่วนตัวไม่ได้ และผู้ดูแลองค์กรเป็นผู้ควบคุมข้อมูลนั้น
  • การย้ายตรงจะยกเลิกแผน Pro และคืนเงินตามสัดส่วนวันที่เหลือ
  • ถ้าออกจากองค์กรภายหลัง ข้อมูลจะอยู่กับองค์กร ไม่ได้ตามตัวคุณไป

แชร์ artifact ในแผน Team

แผน Team ไม่มีการ เผยแพร่ (Publish) ซึ่งคือการเปิดลิงก์ให้ทุกคนบนอินเทอร์เน็ตเข้าดูได้ แต่ แชร์ภายในองค์กร ได้ ทั้งแชร์เฉพาะบางคนหรือแชร์ทั้งองค์กร การจำกัดแบบนี้ทำให้ข้อมูลงานไม่หลุดออกนอกองค์กรโดยไม่ตั้งใจ

แชร์กับใครTeamเงื่อนไข
คนที่ระบุในองค์กรได้เลือกจากปุ่ม Share
ทุกคนในองค์กรได้ผู้ดูแลต้องเปิดฟีเจอร์ Artifacts ไว้
คนนอกองค์กร (Anyone with the link)บางกรณีOwner ต้องเปิด External sharing ใน Organization settings → Artifacts หรืออนุญาตเป็นรายชิ้น
Docs, artifact ที่ใช้ connector หรือที่ถาม Claude ได้นอกองค์กรไม่ได้แม้เปิด External sharing แล้วก็ตาม

ถ้าต้องการหน้าเว็บที่คนนอกองค์กรเปิดได้เสมอ เช่น คู่มือนี้ ให้เก็บไว้บน GitHub Pages คู่กัน

ขั้นตอนการย้าย

  1. Export ข้อมูลเก็บไว้ก่อน ไปที่ Settings → Privacy → Export data ระบบจะส่งลิงก์ดาวน์โหลดทางอีเมล
  2. Export skills ที่สร้างเอง เพราะไม่ย้ายตามไปให้ ส่วน skill ของ Claude Code ใน ~\.claude\skills\ อยู่ในเครื่องอยู่แล้ว
  3. จดรายการ connector ที่ใช้อยู่ ไว้เชื่อมใหม่ในบัญชีองค์กร
  4. คัดลอกไฟล์ HTML ของ artifact ที่เผยแพร่ไว้ เก็บไว้ในเครื่อง หรือย้ายขึ้น GitHub Pages ก่อน เพราะลิงก์สาธารณะจะไม่ย้ายตาม
  5. เข้าร่วมองค์กร Team จากอีเมลเชิญ แล้วเลือกจะย้ายหรือแยกบัญชี
  6. ถ้าเลือกย้าย ให้สลับไปบัญชีองค์กร แล้วไปที่ Settings → Account → Close your personal account
  7. Login Claude Code ใหม่ รัน claude แล้วพิมพ์ /login เลือกบัญชีองค์กร และ sign out แล้ว sign in ใหม่ใน Desktop app
  8. ถ้าค้นหาแชทเก่าไม่เจอ รอให้ระบบจัดทำดัชนีใหม่สักพัก หรือ sign out แล้ว sign in ใหม่
